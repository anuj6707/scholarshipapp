How ScholarMatch Works

Understanding our hybrid architecture, machine learning model integration, and eligibility verification.

1. The Hybrid Recommendation Architecture

ScholarMatch uses a two-stage hybrid recommendation system. Many recommendation engines fail in financial aid because they allow probabilistic models to recommend schemes for which the student violates strict hard legal criteria (e.g. recommending a female-exclusive scholarship to a male applicant).

Rule Engine Priority: The rule-based eligibility engine takes absolute priority over ML scores. If a student fails any hard criterion (gender, age, income ceiling, branch, domicile, disability), the scholarship is marked ineligible and excluded from the primary eligible recommendations.

Only scholarships that pass 100% of hard constraints proceed to scoring and ranking.

2. Machine Learning Model Details

Our ML pipeline is built with scikit-learn and XGBoost:

  • Pipeline Preprocessor: ColumnTransformer with StandardScaler for numerical features (CGPA, percentage, income, age, disability %), OneHotEncoder for categorical attributes (gender, domicile, branch, category), and passthrough for boolean indicators.
  • Classifier: MultiOutputClassifier wrapping 8 independent XGBClassifier models for the primary scholarship targets.
  • Output Metric: Calibrated recommendation affinity score generated using predict_proba.

For the remaining 25+ scholarships without direct ML target columns in the current model, ScholarMatch computes a deterministic rule-based fit score based on academic merit, financial need fit, and eligibility alignment, clearly labeled as "Rule-based match".

3. Research & Data Limitations

Important Notice: The initial recommendation model uses the supplied synthetic student dataset and its existing scholarship target labels. These labels represent scholarship-match classifications in the dataset and should not be interpreted as actual probabilities of receiving a scholarship.

Official eligibility constraints are handled independently through a rule-based eligibility engine. In future iterations, real-world anonymized tracking of applications, institutional quotas, and award outcomes will be utilized to continually train and refine the recommender.
